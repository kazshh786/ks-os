# Phase 3 specialist email assessment

This assessment deliberately keeps website-review, fact-finding and internal operational messages outside the first editable customer-template release. Their content carries workflow state, security and staff-action meaning that should not be exposed through the same unrestricted editor as booking and payment copy.

## Website-review messages

### Current role

- `site-review-invitation` delivers the secure client review invitation.
- `site-review-notification` communicates review progress, changes requested and related updates.
- Links are generated at send time from invitation and review references, revision data and a server-held secret.
- The worker cancels messages whose invitation, review cycle or expiry state is no longer valid.

### Recommendation

Create a separate **Website review emails** editor later with two controlled categories:

1. **Client invitation** — editable subject, heading and introductory paragraph.
2. **Review update** — editable greeting and closing paragraph, with the status-specific core message generated by KS OS.

Keep these elements system-controlled:

- secure review URL and token construction;
- invitation expiry wording;
- review reference and revision;
- current workflow status;
- action button label when the action changes by state;
- cancellation and stale-message rules.

Social promotion can appear in the shared branded footer for client-facing website-review messages, but should never compete visually with the review action button.

## Fact-finding messages

### Current role

- `fact-finding-invitation` starts a secure questionnaire workflow.
- `fact-finding-notification` communicates questionnaire progress, clarification requests and completion-related updates.
- Questionnaire URLs are generated at send time from a short-lived invitation token and configured client origin.
- The worker cancels messages when the invitation is expired or the questionnaire is no longer in an actionable state.

### Recommendation

Create a separate **Fact-finding emails** editor later with:

1. **Initial questionnaire invitation** — editable subject, heading and introductory copy.
2. **Questionnaire update** — editable greeting and support/closing copy around system-generated status text.

Keep these elements system-controlled:

- questionnaire link and invitation token;
- expiry and security wording;
- questionnaire status and clarification state;
- mandatory action text;
- stale-message cancellation.

Client-facing fact-finding messages may use the shared social footer, but the questionnaire CTA remains the primary action.

## Internal operational messages

### Current role

Internal messages include booking changes, operational alerts, scheduled-report readiness and other staff-facing notifications. They are concise action signals rather than customer marketing.

### Recommendation

Do not place internal operational messages in the customer template editor.

A future **Operational notifications** area should provide:

- per-event enable/disable controls;
- recipient rules by owner, assigned team member or role;
- channel choice where supported;
- a short editable prefix or closing note;
- preview examples showing the immutable operational facts.

Keep event facts, customer/service identifiers, dates, amounts, severity and action URLs system-generated. Internal messages should use business branding for trust, but the promotional social panel should be optional or suppressed so staff attention stays on the operational action.

## Release boundary

Phase 3 first release includes editable customer lifecycle templates, prominent branded social links and one selected main booking form. Website-review, fact-finding and internal operational editing should be implemented as separate, permission-aware work after their token and state matrices are reviewed independently.
